## [1.0.2] - 2026-10-25

### Added
- **MCP proxy Kafka SASL support**: librdkafka is now built with the SASL feature (SCRAM-SHA-256/512), so the proxy can deliver audit/trace events to `SASL_PLAINTEXT` listeners with the same `VIRBIUS_KAFKA_SASL_*` configuration control and engine already use. `PLAINTEXT` listeners remain supported (set `VIRBIUS_KAFKA_SECURITY_PROTOCOL=PLAINTEXT`); `SASL_SSL`/PLAIN mechanisms are still not supported. Requires `libsasl2` at build time and `libsasl2-2`/`libgssapi-krb5-2` in the runtime image (Dockerfile updated). Verified end-to-end against a SCRAM-SHA-256 broker with the shipped compose defaults.
- **Audit chain head self-recovery after Redis data loss**: the per-tenant chain head lives only in Redis, so a FLUSHDB / restart-without-persistence / eviction used to restart the chain at seq=1 over already-chained rows — a permanent `seq gap` the verifier reported as tampering. When the head is missing, chaining now rebuilds it from the last chained DB row (`max(audit_seq)` + its `curr_hash`) and logs a warning; the next ingested event resumes the chain from the recovered head. Verified by deleting the Redis head and confirming the follow-up event chains onto the recovered hash with `audit/verify` passing.
- **Remediation rule dedup beyond the idempotency key**: before creating a suggested rule, control now compares the substituted payload against the tenant's existing rules (new `RuleService.listRuleDetails`) — same layer/runtime/intent plus a normalized body match (JSON deep-equality for dsl runtimes, whitespace-collapsed script for groovy) plus scope coverage of the target app (global covers all; `service` requires the app in `app_ids`; `tool` without `app_ids` covers all). A fully-enforcing (`full`) equivalent yields the new `skipped_covered` status with `covered_by`; dry-run/canary/draft equivalents and same-`reason_code` rules surface as `similar_rules` hints in the preview dialog instead. Items within one apply batch dedup against rules created earlier in the same batch. Audit events carry `dedup_layer` (`key`/`equivalent`/`none`). The console shows equivalent/similar rule hints per plan and a `skipped_covered` result state. Covered by six new `RemediationServiceTest` cases (control 411 tests green).
- **Evaluation findings are traceable by risk_id**: the report detail table now shows the full 16-hex `risk_id`, the expanded row exposes the same id with *copy deep link* / *copy suppression entry* actions (a ready-to-paste `.ve-suppress.yaml` stanza whose reason is left as a TODO), and a new filter matches an exact/prefix `risk_id` as well as `check_id`, risk name and evidence paths. `#/evaluation?report=<id>&risk=<risk_id>` deep-links open the report, expand the matching finding, highlight it and scroll it into view (with a retry for the first table render).
- **Evaluation capability diagnostics + REST TargetSpec**: control's settings "test" now appends six capability steps after `license` — `license_features`, `capabilities`, `probe_remote`, `scan_root`, `mcp_egress` and `judge_llm` — so a missing probe gate, missing license feature, unusable scan root, unreachable judge LLM or over-strict egress policy surfaces at test time instead of on the first submit (403/503). Evaluation adds `GET /api/v1/capabilities` (Bearer; booleans/counts/env-var names only — no paths or values) and accepts `target_spec` (YAML/JSON) on `POST /api/v1/evaluations/probes` alongside `identity`; REST is bounded to GET/POST, 64 KB, no CRLF headers, and `{{env:...}}` refs are restricted to the `VE_PROBE_HEADER_` prefix (CLI remains unrestricted), with job views never exposing the spec. The console probe form gains credential identity + TargetSpec paste. Covered by `scripts/test-evaluation-capabilities-e2e.sh` (API-only end-to-end), `EvaluationDiagnosticsServiceTest`, `CapabilityServiceTest`, `TargetSpecRestTest` and `ProbeControllerSpecTest`.
- **Evaluation one-click remediation (M1-min)**: report findings can now carry structured `remediation` plans (eight single-value templates: DLP secrets, high-risk challenge, prompt safety, suspicious-domain block, memory-write challenge, replay high-risk/rate-limit, query rate-limit), with schema validation, dangerous-default rejection, JSON-node placeholder checks and evidence binding. Control adds tenant-scoped `GET .../evaluation/reports/{reportId}/remediation-preview` and `POST .../remediation-apply` (viewer/admin respectively): variables resolve user > bound > default (never guessed), values are whitelisted, and only **dry-run** rules are created — single idempotency key `eval-{check_id}-{risk_id8}` (existing → `skipped_exists`), rollout 429 → `skipped_cap`, license inactive → `40306`, `register_tool`/`egress_allowlist` unsupported, DLP templates normalized to `allow`/risk 0, and an audit event is written with `scene=remediation_apply`. The console gains the generation dialog (danger tags, explicit app-binding confirmation, payload preview, result table with rule deep link). Covered by `scripts/test-remediation-e2e.sh` (control flow) and `tests/test_remediation_flow.sh` (evaluation contract).

### Fixed
- **Unknown routes now return 404 instead of 500**: `NoResourceFoundException` and `NoHandlerFoundException` are handled explicitly, so a typo'd API path no longer falls into the generic 500 handler. Covered by `GlobalExceptionHandlerTest`.
- **License signing failures are diagnosable**: `LicenseSigner` now logs the cause with tenant/app context and falls back to the exception class name when `getMessage()` is null, so the field no longer sees only `failed to sign license: null`. Covered by `LicenseSignerTest`.
- **MySQL/MariaDB schema must be utf8mb4 before migrations**: control/auth now check `@@character_set_database` before Flyway and refuse to start on anything else, preventing latin1 tables on MariaDB. Covered by `DatabaseCharsetGuardTest`.
- **Release and deployment hardening**: CI/release workflows install librdkafka SASL/SSL build deps (Linux and macOS); the offline bundle supports `--platform`, streams `docker save` straight through gzip, and all compose/Helm/script/runbook version pins are now v1.0.2.
- **MySQL timestamp round-trip broke audit/trace hash verification**: control wrote `Instant.toString()` into `TIMESTAMP` columns but hashed the pre-storage ISO string. MySQL hands back a `java.sql.Timestamp` and rounds `TIMESTAMP(0)` writes to the nearest second (not truncation), so the verifier recomputed a different hash for roughly half the rows; a blank `scene` (stored as `event_type`) and the missing `layer` in the trace hash caused the rest. Writes now bind `java.sql.Timestamp`, `MerkleUtil.canonicalTs` folds ISO / driver / epoch-millis forms back to epoch-seconds with MySQL ROUND semantics, and the audit and trace hashes use the same scene fallback and `layer` field as the persisted row. Covered by `HashChainVerifierTest`, `MerkleUtilTest` and `TraceChainVerifierTest`.
- **`tb_agent_trace.tool_args_hash` could not hold the full digest**: `VARCHAR(64)` truncated the `sha256:` + 64-hex (71 chars) value; under MySQL strict mode the plain archive `INSERT` failed, and under relaxed mode the row was stored clipped so `TraceChainVerifier` reported a `curr_hash` mismatch. V36 widens both `tb_agent_trace` and `tb_agent_trace_archive` to `VARCHAR(128)`.
- **MCP proxy token exchange got stuck after a control restart**: a pooled keep-alive connection went stale without a FIN under Docker NAT, turning every evaluate-token exchange into a permanent transport failure until the proxy restarted. The client now uses a 5s pool idle timeout and retries the exchange once.
- **On-prem control/auth wiring**: control now reaches auth over the compose service name (JWKS/token) instead of `127.0.0.1`, the proxy gets `VIRBIUS_AUTH_CONTROL_URL` and the license public-key file, and control baselines Flyway when auth has already created tables in the shared MySQL database.
- **Decision chain now returns one merged read model**: `/trace/session/{id}/timeline` and `/trace/{traceId}/chain` no longer take `include` (the old `steps`/`audit`/`all` modes are gone). Both return trace steps + audit adjudications merged and time-sorted. Audit rows are selected by `session_id` (not by the trace ids of steps), so pure engine input/output review sessions now produce a timeline; edge audit rows map the proxy's `event_type` into `scene` when `scene` is absent, and the proxy now records the decision's `max_risk_score` instead of the session score.
- **Evaluation remediation no longer advertises an unreachable prompt rule**: removed the `prompt_safety` remediation template (engine prompt classification maps guard categories to the built-in `prompt-*` rules, so a generated `prompt_safety_*` rule could never fire). The replay rate template now uses `> 50` rather than `> 100`, below the engine's 60/min per-session cap. `RuleSimulateService` explicitly rejects `lua-dsl`/`dlp-dsl` (the console already hides simulate for them).
- **Production Docker Compose now starts as published**: `docker-compose.prod.yml` had four startup blockers. Kafka used a SASL listener without a broker JAAS entry and defaulted `__consumer_offsets` to RF=3 on a single broker (consumers never joined; control `/ready` stayed 503) — both are now configured. Control was configured to start after engine while engine needs the evaluate-token issuer control writes to Redis, so the engine crash-looped before control; control now starts first and engine depends on it. The control image did not ship `virbius-expr`, silently skipping every gateway Lua rule; the Dockerfile now builds the Go CLI in a dedicated stage and copies it into the control image. The cert-gen sidecar now reuses the MySQL image (which ships OpenSSL) instead of requiring an extra registry image. Verified by building the control image and checking `/usr/local/bin/virbius-expr`, plus a local prod-profile stack where control/engine `/ready` both return 200.
- **`virbius-expr` CLI overwrote the Lua source with action flags**: `--with-action`, `--action`, `--rule-id`, `--reason` and `--risk-score` fell into the positional-argument branch inside the first parse loop, so the compiler received `--with-action` as the script and every gateway Lua rule failed with "script must define `function decide(ctx)`". The first loop now ignores those flags/values; covered by `go test ./...` and an end-to-end compile of a `decide(ctx)` script.
- **Production Flyway installs now backfill seed-only default rules**: prod/staging set `spring.sql.init.mode=never` and run Flyway only, but V1–V34 covered just the rules that changed over time. The initial `prompt-*` set, `cloud_session_risk_escalation`, `edge_dlp_phone`, `edge_l0_content_deny` and the two 1h gateway rate rules existed only in the dev seed, so a fresh MySQL install had 26 of 41 default rules (and missed the `user_req_1h`/`app_req_1h` cumulatives). `V35__backfill_default_rules.sql` inserts the 15 missing rules and 2 cumulatives idempotently (`WHERE NOT EXISTS`, existing operator rules preserved). Verified on MySQL 8: full V1→V35 yields 41 rules (37 full / 4 dry_run) + 3 cumulatives, and re-running V35 keeps 41/3. Future seed-only rule additions must ship a matching migration.
- **License allowlist CSV round-trip no longer flips "wildcard" into "deny everything"**: control persisted `allowed_tools: []` as an empty string and read it back with `"".split(",")` → `[""]`, so the evaluate-token scope denied every tool (`403 capability_denied`) even though virbius-core, the engine and the MCP proxy all define an empty allowlist as "no restriction". `JdbcLicenseRepository` now parses/serializes through the new `LicenseTools` helper (trim, drop blanks, dedupe; empty stays empty) and `LicenseService.issueLicense` normalizes the request/response and avoids an NPE when `allowed_tools` is omitted. Covered by `LicenseToolsTest`; verified end-to-end: an empty list issues → empty token scope → tool calls allowed, while a non-empty list still enforces strict membership.
- **Evaluation diagnostics auth step**: the license probe now sends the configured Bearer token (health stays unauthenticated and exempt), so the settings "test" no longer reports a false auth failure when the evaluation service requires `VE_API_TOKEN`. Covered by `EvaluationDiagnosticsServiceTest`.
- **Replay window bounds normalized to ISO-8601**: control converts MySQL-style `yyyy-MM-dd HH:mm:ss` `since`/`until` bounds to the `T`-separated form stored in `observed_at` before comparing, fixing the `until` edge where string ordering (`'T'` > space) silently dropped boundary rows.
- **`virbius-integrate` accepts dict tool descriptors**: the tool classifier reads `tool_name`/`name` and `description` from mapping-shaped tools as well as attribute-based objects, matching the observed/inventory payloads emitted by the callback.
- **MCP proxy now applies output-review disposal instead of blocking every verdict**: `review_tool_output` previously only handled `block/deny` and replaced the whole tool result with a placeholder, ignoring `disposal_action`/`sanitized_content`. It now applies the same canonical mapping as `virbius-review-sdk`: `redact` → deliver `sanitized_content` (empty string included; missing sanitized text fails closed), `omit` → empty, `reject` → refusal placeholder, `warn` → pass through, unknown/missing disposal → fail closed. The proxy's output-review reply is a typed `OutputReviewResponse` whose required `disposal_action` makes an engine contract violation surface as an engine error (following `fail_open`). Each intervention records an edge audit row (`event_type=output_review`, `reason_code=output_review:<disposal>`) so the proxy layer is no longer silent about output review.
- **Engine now attributes allow-only decisions to the concrete allow rule instead of `POLICY_ALLOW`**: when an allow exception suppressed a deny/challenge hit but the primary pool contained no enforced hit, `ActionMerge` previously fell back to `POLICY_ALLOW`, erasing attribution. It now falls back to the highest-risk enforced allow hit (`riskScore, ruleRevision, ruleId` tie-break), while `POLICY_ALLOW` remains the sentinel for "no rule hit" or dry-run-only allow candidates. A new `MergeResult.suppressed` flag (surfaced through `EngineDecisionDto.suppressed`) marks true suppression, and `AuditWriter` free-sampling for allow decisions is now gated on `decision.suppressed()` instead of `ruleId != POLICY_ALLOW`, so wide allow rules no longer exempt all benign traffic from the audit chain. Attribution convention: allow attribution reads `(allow, X)` as "X = suppressed deny rule" (suppression) or "X = the allow rule itself" (allow-only); allow-rule `risk_score` acts as attribution tie-break priority only and does not affect the decision score (merged risk stays 0).

## [1.0.0] - 2026-10-19

### Added
- **Typed decision + structured denial (SDK)**: `VirbiusGuard.precheck()` now returns a `VirbiusDecision` — attribute-first (`d.allowed` / `d.reason` / `d.reason_code` / `d.fast_path` / `d.sandbox_type`), still subscriptable (`d["allowed"]`) and `to_dict()`-serializable — aligning with AGT's `evaluation`/`verdict`. Denials are built via `VirbiusDenied.from_decision(decision)`, carrying the structured `decision`; the message stays single-sourced through `policy_blocked_message`. No audit reference is carried in-process (the pre-check emits no audit record synchronously; a real decision/audit id would need the binding/engine to return one).
- **Framework-agnostic SDK entry point `govern()`**: `virbius-mcp-python` now exposes a module-level `govern(fn, *, name=None, guard=None)` — wrap **any** callable so every call is pre-checked against the license allowlist (`VirbiusDenied` on refusal) with no agent framework required; usable bare or as a decorator, and supporting `async def` (the pre-check runs before the call is awaited). It is now the headline path, and the OpenAI/LangChain adapters (`openai_tool` / `langchain_tool`) plus `VirbiusGuard.guarded` are thin layers over the same enforcement core (the three duplicated wrapper bodies are gone). Credential is read lazily from the environment (`from_env()`, cached) when no `guard` is passed.
- **OSS-agent demo covers the SDK口径**: `examples/oss-agent-target/target_agent.py` now exercises the framework-agnostic `govern(fn)` (`sdk probe`) and the LangChain adapter (`sdk langchain`), and `scripts/oss-agent-e2e-sdk.sh` asserts both — govern allow/deny plus the model-visible refusal message, and the LangChain `handle_tool_error` message — alongside the existing precheck/review checks. The demo README now frames VirbiusAgent's **three** integration modes (this rig = proxy + SDK embed; the Higress gateway has its own e2e). `langchain-core` added to the demo deps.
- **Integration UX — MCP proxy CLI + Python SDK**: `virbius-mcp-proxy --config <path>` (an explicit file must parse — no silent fallback; a search-path file that exists yet fails to parse now warns), `virbius-mcp-proxy doctor` (pre-flight: config summary, public-key/license validation with days remaining, connectivity probes for engine/control/token-exchange/upstreams), `virbius-mcp-proxy enroll` (one command fetches tenant→tools→license→public key; admin credential is env-only `VIRBIUS_ADMIN_API_KEY`, files written mode 0600, the JWT is never printed, `--revoke` replaces an existing license), a runtime operator surface (`GET /status` on tcp/http; the `virbius/status` JSON-RPC method for stdio) exposing wiring + fallback-license verification + the last 50 decisions (including allows the audit sampling dropped), and opt-in `VIRBIUS_BASE_URL` single-base derivation (control + token exchange + engine `:8082`, explicit config still wins). Python: `virbius-mcp-python` is now a mixed Rust/Python package adding `VirbiusGuard` (stateful precheck reading the proxy's own env names; `openai_tool` / `langchain_tool` / `guarded` decorators) and `virbius_tool_error` (a pass-through failure formatter for proxy mode that reveals the proxy's human denial message instead of the Agents SDK's generic retry text), plus `VirbiusDenied` (a `PermissionError` subclass carrying `reason_code`). Verified by `scripts/test-mcp-proxy-stdio-e2e.sh` (9/9), `scripts/oss-agent-e2e-{proxy,sdk}.sh` (8/8, 6/6) and `scripts/test-mcp-proxy-audit-e2e.sh` (15/15).

Informational, never gates; `--self-test` verifies the logic without API calls and it SKIPs (exit 77) without a key.

### Fixed
- **Challenge-token bypass removed (audit/trace gap closed)**: the proxy no longer short-circuits on `_meta.challenge_token` — the bypass branch in `router.rs` and the now-unused `SecurityPipeline::extract_challenge_token` / `verify_challenge_token` are deleted. A retry after challenge approval flows through the normal pipeline: the engine's session-level exemption (written at approve time, `challenge:exempt:*`, TTL `virbius.challenge.exemption-ttl-seconds`, default 600s, bound per the tool's `approval_mode`) turns the challenge into `allow`, so the retried call gets full evaluation plus edge+cloud audit rows and an Agent-trace step. This closes the gap where an approved replay executed with no audit and no trace (asserted end-to-end by the outline script's §7.5). `_meta.challenge_token` is still accepted for client compatibility but is never verified and is stripped before forwarding upstream (`patch_forward_params`); `/v1/challenge/verify` is no longer called by the proxy (kept for compatibility). Note: the exemption only overrides a `challenge` disposition — a retry that evaluates to `deny` is still blocked — and with `exemption-ttl-seconds=0` an approved challenge can no longer be retried successfully.
- **Operator identity on approvals / alert acks**: the console no longer hard-codes the placeholder `"operator"`. New shared `OperatorResolver` (`io.virbius.control.common`) resolves the actor as explicit client value → `X-User-Id` header → authenticated principal → `"unknown"` fallback; `ChallengeController.approve/reject` and `AlertController.ack` use it (blank input now records a real or honest identity, never `"operator"`), and `DeployRolloutController` delegates to the same resolver (behavior unchanged, fallback `"system"`). The console top bar gains a persisted **Operator** name field that prefills the challenge approval/reject dialog and the alert-ack prompt; both dialogs require a non-empty actor. Covered by `OperatorResolverTest`, `ChallengeControllerTest`, and shell-level identity assertions in both e2e scripts.
- **Outline script: repo-root variable clobbered by the Merkle root**: `scripts/test-eval-outline-sdk.sh` assigned the Merkle proof's `root_hash` to `ROOT`, overwriting the repo-root path variable — every later `"$ROOT/..."` path check silently failed (including the §4.1 `IntentAlignmentDetector` source probe, which then always reported "not implemented"). The clobbering block was removed together with the Merkle proof feature (see below), and the guardrails script keeps the repo path in a dedicated `REPO_ROOT` separate from positional vars; a CI step runs `bash -n` over `scripts/*.sh` so a syntax regression of this class fails the build.
- **Multi-replica correctness fixes (audit · blacklist · chain)**:
  - **Hash chain** — when the CAS retries are exhausted, the batch's `audit_seq`/`prev_hash`/`curr_hash` are now cleared, so the ingestor no longer persists chain values the chain state never advanced to (which forked the per-session chain); the MySQL fallback is a bounded 3-attempt loop (was unbounded recursion).
  - **Archive mirrors** — the retention `DuplicateKeyException` guard is live on MySQL: both `tb_audit_events_archive` and `tb_agent_trace_archive` inherit the base tables' unique keys through `CREATE TABLE ... LIKE` (V1 declares `UNIQUE(event_id)` and `UNIQUE(trace_id, step_id)`). The SQLite dev schema declares the audit-archive index explicitly (parity); no migration was required.
  - **Daily anchor** — sealing is insert-if-absent; the previous `DELETE`+`INSERT` let a slower replica overwrite an already-committed (possibly externally timestamped) seal.
  - **Image blacklist** — the rebuild is single-flight (Redis lock) and the staging→live swap is one atomic `RENAME`+`PERSIST`; previously two replicas could resurrect a removed list, and a crash between rename and persist left the live key on the 120s staging TTL (silently expiring the blacklist).
  - **Consumer groups** — pending entries are drained before a group is destroyed on shutdown (no lost update across a graceful restart), and a startup janitor destroys groups left by dead pods.
  - **instance-id** — a blank `VIRBIUS_INSTANCE_ID`/hostname now logs an error (per-instance groups and the canary bucket need a unique id); the silent `unknown-<pid>` fallback could collide on bare-metal/systemd HA.
  - **Redis-degradation metric** — `micrometer-registry-prometheus` added, so the `virbius.redis.fallback` counter (Prometheus `virbius_redis_fallback_total`) is actually scrapeable.
- **Control `BusinessException` HTTP status mapping**: `GlobalExceptionHandler.handleBusiness` mapped only `404`/`409` to their real HTTP status and collapsed every other domain code (`401`/`403`/`423`/`429`/`502`/`503`…) into `400`. Auth failures (`401`), authorization (`403`), throttling (`429`, which clients/tests branch on for `Retry-After`) and upstream errors (`502`/`503`, which clients retry) were all misreported as `400`. The handler now resolves the status via `HttpStatus.resolve(code)` (falling back to `400` only for unknown or non-error codes); the JSON body always carried the original code and is unchanged. Covered by `virbius-control` `GlobalExceptionHandlerTest`.
- **License verification error opacity + PEM robustness**: `LicenseError` was a single misleading `InvalidSignature` covering three unrelated causes (an `app_id` mismatch, an unparseable public key, a bad signature) — impossible to self-diagnose. It is now `AppIdMismatch{jwt,session}` / `KeyParseFailed` / `SignatureInvalid` with context in the `Display`/deny reason, and the `license_public_key` PEM is trimmed before parsing so a file ending in a blank line verifies instead of failing. Audited deny reasons are capped at 64 chars on the wire (control's `reason_code` is `VARCHAR(64)`; a longer value would make MySQL strict mode reject the whole audit row).
- **Machine-readable precheck code + human-readable proxy errors**: `virbius-core` `precheck` now returns a stable `code` (`not_in_allowlist` / `schema_violation`), surfaced through the Python and Node bindings, so `VirbiusGuard.guard()` sets `VirbiusDenied.reason_code` from the code instead of guessing from the message text. Proxy policy/operational errors now carry a human `message` + `data.reason_code` (was: the message was the bare code); upstream/transport errors (`-32603`) use a fixed, sanitized message (no raw error text, which could carry internal hosts/URLs). The Node binding reports license errors via `Display`, matching the Python binding. Deferred: the engine path still surfaces an engine `reason_code` as its detail (needs an engine `reason` field), and the audit `reason_code` column is not yet re-homed.
- **SDK: rate-limited review could pass unreviewed (429 × fail_open)**: a throttled call surfaced as a generic transport failure and followed `fail_open=True`, so a client that deliberately flooded the engine's rate limiter would have every subsequent window forwarded unreviewed — a review bypass. 429 now fails CLOSED **unconditionally** (`ReviewError`, no fail-open opt-in — a throttle is a deliberate engine decision, and an escape hatch would let a flooding client forward unreviewed content); the single remaining policy is `fail_open` (outages only). The built-in requests/httpx transports return the engine's 429 JSON body instead of raising, and the custom-transport contract (429 must be returned, not raised) is documented.
- **Output-review statistics & Merkle inclusion proofs removed pre-GA**: the `GET .../audit/output-review-stats` and `GET .../audit/proof/{eventId}` / `POST .../audit/verify-proof` endpoints, the `MerkleAuditService`, and the console's 输出误拦 / Merkle 证明 tabs were dropped before tagging, so they never ship in 1.0.0. Hash-chain verification, the daily Merkle anchor (`MerkleUtil` retained), Decision BOM, and the audit export are unaffected.
- **Alert flooding per review window**: alerts keyed on `event_id`, so a blocked streaming answer (one deny audit event per window) opened one alert per window. Alerts now aggregate per answer — `alert-{tenant}-{trace}` with the existing NOT-EXISTS insert collapsing the whole trace to a single alert (every window stays visible in the alert's Decision BOM); blank `trace_id` still falls back to per-event alerts.
- **Alert status naming inconsistency**: `AlertService` wrote `status='ack'` while the console filtered and rendered `acked`, so the `?status=acked` filter was always empty, the ack button never greyed out, and a repeat ack still returned `acknowledged=false`. Unified on `acked`.
- **Dev schema drift**: `tb_agent_trace` was missing `chain_seq` / `tool_result_preview` / `prev_hash` / `curr_hash` on databases created before migrations `V13`/`V14` (dev disables Flyway), which made `/audit/trace-chain/verify`, `/audit/decision-bom/{id}` and `/alerts/{id}/bom` return 500. Resolved by rebuilding the dev DB (`VIRBIUS_REBUILD_DB=1`); `db/schema.sql` now carries these columns for fresh dev databases.
- **`virbius-integrate` `strict=True` crashed with `AttributeError`**: `VirbiusAuditCallback.__init__` called a `_startup_check` method that was never implemented, so strict startup mode failed immediately. It is now a real synchronous startup handshake (reachability + token + route; `handshake_deep` adds an ingest round-trip) that raises `VirbiusIntegrateError` with a reason.
- **Delegated credential plane — delete-to-zero snapshot cleanup**: deleting the last credential while Redis was unavailable left a stale snapshot, so the deleted credential stayed injected. Control's 60s self-heal now reconciles the union of tenants with DB rows and tenants still holding a Redis snapshot key, republishing each tenant's current active set — so the deleted-to-zero case gets an authoritative empty doc that clears the proxy vault (no extra bookkeeping table).
- **Delegated value validation ↔ proxy alignment**: `value` now rejects all control characters (0x00–0x1F, 0x7F), matching the proxy's `HeaderValue` acceptance, so a value the Control accepts can no longer fail at injection time; obs-text (≥0x80) is still allowed.
- **MySQL/MariaDB was missing tables/columns that existed only in the SQLite dev schema**: `tb_proxy_policy` (read/written by `ProxyPolicyService`) had no migration, so the proxy-policy admin API failed with "table doesn't exist" on prod; `tb_agent_trace.tool_args` (written by `TraceEventIngestor`, read by `DecisionBomService`) was likewise absent and broke trace ingest. Added migrations `V17__proxy_policy.sql` and `V18__trace_tool_args.sql` (the latter also adds the column to the `LIKE`-derived `tb_agent_trace_archive`). A new `SchemaDialectParityTest` (control + auth) fails the build whenever `db/schema.sql` and `db/migration/*.sql` drift in tables or columns.
- **`virbius-auth` prod profile was SQLite-only**: `application-prod.yml` was identical to dev (`jdbc:sqlite:`), so the auth service could not run on MySQL in production. Added the MariaDB driver + Flyway, a MySQL datasource, and `db/migration/V1__baseline.sql`; dev keeps SQLite via `db/schema.sql`.
- **MySQL session timezone vs UTC-stored timestamps**: control prod/staging now pin each connection to UTC (`connection-init-sql: SET time_zone = '+00:00'`, overridable via `VIRBIUS_JDBC_INIT_SQL`) so `NOW()`/`CURRENT_TIMESTAMP` agree with the ISO-UTC strings the app writes (SQLite's `CURRENT_TIMESTAMP`/`datetime('now')` are already UTC).
- **Audit chain self-inflicted seq holes (ingest order)**: `AuditEventIngestor` advanced the shared Redis chain head **before** the `INSERT OR IGNORE`, so any duplicate delivery (Kafka is at-least-once: redelivery after a rebalance or a crash) advanced the head with no row and the next event landed on a skipped seq — `HashChainVerifier` then reported `seq gap` on legitimately ingested events, and a crash between chain and insert advanced the head with no row at all. The order is now insert → advance head → stamp the row (mirroring `TraceEventIngestor`): a duplicate insert of an already-chained row is a no-op, a duplicate of a row still at `audit_seq=0` (crash between insert and chain) is repaired on redelivery, and a permanently unchained row surfaces as an explicit `unchained row` verifier reason instead of a misleading `seq gap`. Regression-tested by `AuditEventIngestorIdempotencyTest` (redelivery / crash-repair / visible-break).
- **SQL chain-state fallback was broken on SQLite**: `HashChainOrchestrator.chainBatchMysql` opened with a `SELECT ... FOR UPDATE` whose result was never used — a no-op lock under JdbcTemplate auto-commit and a syntax error on SQLite, so the fallback silently never chained anything on the dev dialect. Removed; mutual exclusion remains the version-column CAS on the UPDATE.
- **Approval queue API never returns an empty/erroring body**: control's `ChallengeController` proxied engine failures into `HTTP 500` with `Content-Length: 0`, which broke the console (`Unexpected end of JSON input`). Every failure path now returns a non-empty `application/json` body on the control-wide `ApiResult` envelope (`{code,message}`; the engine `readJson`/`adminFetch` client tolerates both), an engine 5xx is no longer misreported as `400 challenge not found` (404 is the only not-found), and approve/reject verify the engine status before parsing. Covered by `ChallengeControllerTest` (unreachable / empty-500 / non-JSON-200 / engine-5xx pre-fetch / non-pending).
- **Docker build was broken on any host whose Docker client injects a proxy** (`~/.docker/config.json` `proxies`): BuildKit injects the client proxy into `RUN` steps and it overrides `ENV` clears, so a dead/unreachable proxy made `npm ci` die with `ECONNREFUSED` — and npm's crash exits 0, surfacing as the misleading `npm run build` exit 127 (`vue-tsc: not found`). The build now clears proxy vars per network-calling `RUN` (Java package, cargo, apt, pip), defaults the npm registry to npmmirror (`--build-arg NPM_REGISTRY=` restores npmjs), and the console frontend downloads Node from the npmmirror binary mirror. `.dockerignore` also excludes host-built `frontend/node`/`node_modules` (a macOS Node made the plugin skip its Linux download) and the ~100GB `virbius-guard/` training data plus other non-build directories (build context 239MB→~6MB).

- **Go virbius-audit Falco Plugin**: C-shared library consuming Redis Stream audit events with PID map association.
- **Rust config_subscriber**: Redis Stream → `/etc/falco/falco_rules.d/` → SIGHUP reload.
- **Prompt Injection Detection**: single-model (Qwen3Guard) semantic detection with dynamic risk scoring.
- **STI Taint Tracking**: cross-tool untrusted output propagation detection.
- **Hash Chain Audit Integrity**: SHA-256 hash chain for tamper-proof audit logs (Oracle + Redis Lua CAS).
- **Agent Runtime License System**: Ed25519-signed JWT licenses with revocation support.
- **Audit Dashboard**: session risk, tool calls, alerts, approval queue, decision trace visualization.
- **Edge Manifest Compilation**: per-app manifest partitioning with global/service/tool bind scopes.
- **Falco Plugin K8s Deployment**: DaemonSet + ConfigMap + config-subscriber sidecar.

### Security
- API key authentication with SHA-256 hashed credentials and role-based access control.
- Three-level fallback policy: MinimumPrivilege, DefaultDeny, AuditOnly with fail-open/fail-closed.
- DLP/PII desensitization for phone numbers, ID cards, email, bank cards.
