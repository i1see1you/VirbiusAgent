### Added
- **Typed decision + structured denial (SDK)**: `VirbiusGuard.precheck()` now returns a `VirbiusDecision` — attribute-first (`d.allowed` / `d.reason` / `d.reason_code` / `d.fast_path` / `d.sandbox_type`), still subscriptable (`d["allowed"]`) and `to_dict()`-serializable — aligning with AGT's `evaluation`/`verdict`. Denials are built via `VirbiusDenied.from_decision(decision, *, audit_ref=None)`, carrying the structured `decision` plus an optional audit reference (`exc.audit_record()`); the message stays single-sourced through `policy_blocked_message`. Phase 1 (SDK-side): `audit_ref` is caller-supplied — the in-process pre-check does not emit an audit record synchronously (that needs the binding/engine to return a decision id).
- **Framework-agnostic SDK entry point `govern()`**: `virbius-mcp-python` now exposes a module-level `govern(fn, *, name=None, guard=None)` — wrap **any** callable so every call is pre-checked against the license allowlist (`VirbiusDenied` on refusal) with no agent framework required; usable bare or as a decorator, and supporting `async def` (the pre-check runs before the call is awaited). It is now the headline path, and the OpenAI/LangChain adapters (`openai_tool` / `langchain_tool`) plus `VirbiusGuard.guarded` are thin layers over the same enforcement core (the three duplicated wrapper bodies are gone). Credential is read lazily from the environment (`from_env()`, cached) when no `guard` is passed.
- **OSS-agent demo covers the SDK口径**: `examples/oss-agent-target/target_agent.py` now exercises the framework-agnostic `govern(fn)` (`sdk probe`) and the LangChain adapter (`sdk langchain`), and `scripts/oss-agent-e2e-sdk.sh` asserts both — govern allow/deny plus the model-visible refusal message, and the LangChain `handle_tool_error` message — alongside the existing precheck/review checks. The demo README now frames VirbiusAgent's **three** integration modes (this rig = proxy + SDK embed; the Higress gateway has its own e2e). `langchain-core` added to the demo deps.
- **Integration UX — MCP proxy CLI + Python SDK**: `virbius-mcp-proxy --config <path>` (an explicit file must parse — no silent fallback; a search-path file that exists yet fails to parse now warns), `virbius-mcp-proxy doctor` (pre-flight: config summary, public-key/license validation with days remaining, connectivity probes for engine/control/token-exchange/upstreams), `virbius-mcp-proxy enroll` (one command fetches tenant→tools→license→public key; admin credential is env-only `VIRBIUS_ADMIN_API_KEY`, files written mode 0600, the JWT is never printed, `--revoke` replaces an existing license), a runtime operator surface (`GET /status` on tcp/http; the `virbius/status` JSON-RPC method for stdio) exposing wiring + fallback-license verification + the last 50 decisions (including allows the audit sampling dropped), and opt-in `VIRBIUS_BASE_URL` single-base derivation (control + token exchange + engine `:8082`, explicit config still wins). Python: `virbius-mcp-python` is now a mixed Rust/Python package adding `VirbiusGuard` (stateful precheck reading the proxy's own env names; `openai_tool` / `langchain_tool` / `guarded` decorators) and `virbius_tool_error` (a pass-through failure formatter for proxy mode that reveals the proxy's human denial message instead of the Agents SDK's generic retry text), plus `VirbiusDenied` (a `PermissionError` subclass carrying `reason_code`). Verified by `scripts/test-mcp-proxy-stdio-e2e.sh` (9/9), `scripts/oss-agent-e2e-{proxy,sdk}.sh` (8/8, 6/6) and `scripts/test-mcp-proxy-audit-e2e.sh` (15/15).

### Fixed
- **Control `BusinessException` HTTP status mapping**: `GlobalExceptionHandler.handleBusiness` mapped only `404`/`409` to their real HTTP status and collapsed every other domain code (`401`/`403`/`423`/`429`/`502`/`503`…) into `400`. Auth failures (`401`), authorization (`403`), throttling (`429`, which clients/tests branch on for `Retry-After`) and upstream errors (`502`/`503`, which clients retry) were all misreported as `400`. The handler now resolves the status via `HttpStatus.resolve(code)` (falling back to `400` only for unknown or non-error codes); the JSON body always carried the original code and is unchanged. Covered by `virbius-control` `GlobalExceptionHandlerTest`.
- **License verification error opacity + PEM robustness**: `LicenseError` was a single misleading `InvalidSignature` covering three unrelated causes (an `app_id` mismatch, an unparseable public key, a bad signature) — impossible to self-diagnose. It is now `AppIdMismatch{jwt,session}` / `KeyParseFailed` / `SignatureInvalid` with context in the `Display`/deny reason, and the `license_public_key` PEM is trimmed before parsing so a file ending in a blank line verifies instead of failing. Audited deny reasons are capped at 64 chars on the wire (control's `reason_code` is `VARCHAR(64)`; a longer value would make MySQL strict mode reject the whole audit row).
- **Machine-readable precheck code + human-readable proxy errors**: `virbius-core` `precheck` now returns a stable `code` (`not_in_allowlist` / `schema_violation`), surfaced through the Python and Node bindings, so `VirbiusGuard.guard()` sets `VirbiusDenied.reason_code` from the code instead of guessing from the message text. Proxy policy/operational errors now carry a human `message` + `data.reason_code` (was: the message was the bare code); upstream/transport errors (`-32603`) use a fixed, sanitized message (no raw error text, which could carry internal hosts/URLs). The Node binding reports license errors via `Display`, matching the Python binding. Deferred: the engine path still surfaces an engine `reason_code` as its detail (needs an engine `reason` field), and the audit `reason_code` column is not yet re-homed.
- **SDK: rate-limited review could pass unreviewed (429 × fail_open)**: a throttled call surfaced as a generic transport failure and followed `fail_open=True`, so a client that deliberately flooded the engine's rate limiter would have every subsequent window forwarded unreviewed — a review bypass. 429 now fails CLOSED **unconditionally** (`ReviewError`, no fail-open opt-in — a throttle is a deliberate engine decision, and an escape hatch would let a flooding client forward unreviewed content); the single remaining policy is `fail_open` (outages only). The built-in requests/httpx transports return the engine's 429 JSON body instead of raising, and the custom-transport contract (429 must be returned, not raised) is documented.
- **Output-review stats ignored allow sampling**: the engine publishes allow events at `virbius.audit.sample-rate-allow` (default 0.1) while deny events are complete, so the answer-level `total`/`deny_rate` understated allowed answers ~10× and inflated the deny rate. `outputReviewAnswerStats` now reweights observed allow-only answers Horvitz–Thompson style (inclusion probability `1-(1-rate)^k`, mirroring `bumpRequestStats`' event-level reweighting) and exposes `allowed` (estimate) + `sampled_allow_answers` (raw observed count); `denied_answers` stays exact.
- **Alert flooding per review window**: alerts keyed on `event_id`, so a blocked streaming answer (one deny audit event per window) opened one alert per window. Alerts now aggregate per answer — `alert-{tenant}-{trace}` with the existing NOT-EXISTS insert collapsing the whole trace to a single alert (every window stays visible in the alert's Decision BOM); blank `trace_id` still falls back to per-event alerts.
- **Alert status naming inconsistency**: `AlertService` wrote `status='ack'` while the console filtered and rendered `acked`, so the `?status=acked` filter was always empty, the ack button never greyed out, and a repeat ack still returned `acknowledged=false`. Unified on `acked`.
- **Dev schema drift**: `tb_agent_trace` was missing `chain_seq` / `tool_result_preview` / `prev_hash` / `curr_hash` on databases created before migrations `V13`/`V14` (dev disables Flyway), which made `/audit/trace-chain/verify`, `/audit/decision-bom/{id}` and `/alerts/{id}/bom` return 500. Resolved by rebuilding the dev DB (`VIRBIUS_REBUILD_DB=1`); `db/schema.sql` now carries these columns for fresh dev databases.
- **`virbius-integrate` `strict=True` crashed with `AttributeError`**: `VirbiusAuditCallback.__init__` called a `_startup_check` method that was never implemented, so strict startup mode failed immediately. It is now a real synchronous startup handshake (reachability + token + route; `handshake_deep` adds an ingest round-trip) that raises `VirbiusIntegrateError` with a reason.
- **Delegated credential plane — delete-to-zero snapshot cleanup**: deleting the last credential while Redis was unavailable left a stale snapshot, so the deleted credential stayed injected. Control's 60s self-heal now reconciles the union of tenants with DB rows and tenants still holding a Redis snapshot key, republishing each tenant's current active set — so the deleted-to-zero case gets an authoritative empty doc that clears the proxy vault (no extra bookkeeping table).
- **Delegated value validation ↔ proxy alignment**: `value` now rejects all control characters (0x00–0x1F, 0x7F), matching the proxy's `HeaderValue` acceptance, so a value the Control accepts can no longer fail at injection time; obs-text (≥0x80) is still allowed.
- **MySQL/MariaDB was missing tables/columns that existed only in the SQLite dev schema**: `tb_proxy_policy` (read/written by `ProxyPolicyService`) had no migration, so the proxy-policy admin API failed with "table doesn't exist" on prod; `tb_agent_trace.tool_args` (written by `TraceEventIngestor`, read by `DecisionBomService`) was likewise absent and broke trace ingest. Added migrations `V17__proxy_policy.sql` and `V18__trace_tool_args.sql` (the latter also adds the column to the `LIKE`-derived `tb_agent_trace_archive`). A new `SchemaDialectParityTest` (control + auth) fails the build whenever `db/schema.sql` and `db/migration/*.sql` drift in tables or columns.
- **`virbius-auth` prod profile was SQLite-only**: `application-prod.yml` was identical to dev (`jdbc:sqlite:`), so the auth service could not run on MySQL in production. Added the MariaDB driver + Flyway, a MySQL datasource, and `db/migration/V1__baseline.sql`; dev keeps SQLite via `db/schema.sql`.
- **MySQL session timezone vs UTC-stored timestamps**: control prod/staging now pin each connection to UTC (`connection-init-sql: SET time_zone = '+00:00'`, overridable via `VIRBIUS_JDBC_INIT_SQL`) so `NOW()`/`CURRENT_TIMESTAMP` agree with the ISO-UTC strings the app writes (SQLite's `CURRENT_TIMESTAMP`/`datetime('now')` are already UTC).
- **Audit chain self-inflicted seq holes (ingest order)**: `AuditEventIngestor` advanced the shared Redis chain head **before** the `INSERT OR IGNORE`, so any duplicate delivery (Kafka is at-least-once: redelivery after a rebalance or a crash) advanced the head with no row and the next event landed on a skipped seq — `HashChainVerifier` then reported `seq gap` on legitimately ingested events, and a crash between chain and insert advanced the head with no row at all. The order is now insert → advance head → stamp the row (mirroring `TraceEventIngestor`): a duplicate insert of an already-chained row is a no-op, a duplicate of a row still at `audit_seq=0` (crash between insert and chain) is repaired on redelivery, and a permanently unchained row surfaces as an explicit `unchained row` verifier reason instead of a misleading `seq gap`. Regression-tested by `AuditEventIngestorIdempotencyTest` (redelivery / crash-repair / visible-break).
- **SQL chain-state fallback was broken on SQLite**: `HashChainOrchestrator.chainBatchMysql` opened with a `SELECT ... FOR UPDATE` whose result was never used — a no-op lock under JdbcTemplate auto-commit and a syntax error on SQLite, so the fallback silently never chained anything on the dev dialect. Removed; mutual exclusion remains the version-column CAS on the UPDATE.

### Changed
- **Dependency security bump (RUSTSEC advisories)**: `rustls` `0.23.45 → 0.23.46` and `quinn-proto` `0.11.15 → 0.11.19` (`Cargo.lock`) resolve the 9 advisories `RUSTSEC-2026-0338…0349` (rustls patched `>=0.23.46`; quinn-proto patched `>=0.11.18`) flagged by `cargo audit`. `cargo check --workspace` passes.
- **README comparison refreshed (bilingual)**: the "Comparison with Industry Solutions" table now compares the three closest open-source peers — **Microsoft Agent Governance Toolkit** (MIT), **Meta LlamaFirewall** (open source, Llama Community License) and **IBM ContextForge / `mcp-context-forge`** (Apache-2.0) — replacing the dated NeMo Guardrails / Guardrails AI / Snyk Agent Scan columns; rows re-derived from each project's public docs, and the summary disclaimer updated.
- **`role` is a closed enum on `POST /v1/evaluate`** (new project, no compat burden): `input | output | tool_call`, blank = `tool_call` semantics; any other value — including the legacy `user` — returns `400 unsupported_role` (with `supported_roles` in the body) so a mis-integrated caller fails loudly instead of silently running an undocumented role. `virbius-demo`'s input review migrated `role=user` → `role=input` (gains: never challenged, per-trace risk dedup); DEPLOYMENT's application-integration guidance now says `role="input"` (the out-of-repo APISIX `virbius-guard` plugin / gateway-agent must switch before launch). The role side-effect matrix is now three rows.
- **SDK: `disposal_action` is strict**: a `role=output` response without `disposal_action` now raises `ReviewError` (contract violation; engine and SDK ship together) instead of silently deriving one. Locally synthesized fail-open verdicts still derive `warn`/`reject`.
- **Alerts carry `session_id`**: engine audit events now include `session_id` in the Kafka payload (not persisted in `tb_audit_events`), and `AlertService` binds it into `tb_alert` instead of hard-coding `NULL` — the console can correlate an alert directly with its session.
- **Config namespace unified under `virbius.`**: the `audit.*`, `trace.*`, `integrate.*` and `rollout.*` property namespaces (and the env-style `VIRBIUS_AUTH_DATA_DIR`) now live under `virbius.*` — `virbius.audit.*`, `virbius.trace.*`, `virbius.integrate.*`, `virbius.rollout.*`, `virbius.data-dir` — in both code (`@Value` / `@KafkaListener` / `@Scheduled`) and `application*.yml`, which is now fully nested under a single `virbius:` block (a stray dotted `virbius.audit.hash-chain:` key was folded in too). Implied env names follow suit (e.g. `INTEGRATE_INGEST_TOKEN` → `VIRBIUS_INTEGRATE_INGEST_TOKEN`). No functional change.
- **Delegated redaction covers encoding variants**: body/location redaction now also replaces percent/base64/base64url literal forms of the credential (literal replacement only — the body is never decoded/rewritten); a response whose raw body contains the credential raises a `hit_credential_echo` alert.
- **Proxy test seam**: added a `test-harness` cargo feature (compile-time only) so the full-chain E2E harness can drive the hit branch against a local HTTP server; a production binary cannot disable the https+443 gate via any runtime variable.
- **Dev seed builtin rules grouped under `system-builtin`**: the 3 Falco builtin rules in `db/seed.sql` now carry `bundle_id='system-builtin'` (matching prod migration `V2`) instead of `demo-default`, so the builtin ruleset is identical across dev and prod; the demo ruleset remains dev-only.
- **Local dev isolation (`run-local.sh`)**: defaults to Redis DB 1 (`VIRBIUS_REDIS_DB`, overridable; DB 0 stays reserved for the E2E harnesses) and refuses to start beside a live `virbius-control` process — the audit chain head is coordinated in shared Redis while each control writes rows into its own database, so a second instance consuming the same topics leaves both databases with a gappy `audit_seq` that looks like tampering.

### Removed
- **Chat-embedded input/output review and chat trace steps; the chat endpoint itself**: `/v1/chat/completions` no longer reviews content or publishes `input`/`output` trace steps — and the endpoint is now **removed from the engine entirely** (it had degenerated into a pure local-Ollama passthrough facade with no review value: production routes traffic through the APISIX/Higress gateway or the SDK, and Ollama natively exposes an OpenAI-compatible endpoint, so callers stream from their LLM directly). ## [0.2.0] - 2026-09-15

### Changed
- Route→Tool migration: replaced `route` bind_scope with `tool` scope for Agent security rules.
- Falco reverted to a pure system-level syscall observation role (Plan A): cross-layer correlation (syscall events ↔ Agent session context) is now resolved by the Engine's `FalcoAlertController` via Redis pidmap lookup, instead of injecting context fields inside the Falco engine.
- `virbius-kernel/deploy/falco-config.yaml`: switched from `program_output` to `http_output`, pointing at the Engine internal endpoint, with `connection_keepalive` + `retry_wait_seconds` support.
- `virbius-kernel/deploy/kustomization.yaml`: removed plugin-specific resource references, added `engine-service.yaml`.

### Added
- **`virbius-engine/.../FalcoAlertController.java`**: new `POST /api/internal/falco-alert` endpoint that receives Falco `http_output` native JSON, parses `output_fields["proc.pid"]`, resolves session_id via Redis `pid_trace:{host_pid}` reverse lookup, and calls `SessionRiskManager.onFalcoAlert(sessionId)` to increment the `falco_pending` counter. Includes ppid fallback logic.
- **`FalcoAlertController.lookupSessionByCgroup()`** (P1): three-level correlation chain `host_pid → cgroup_id → ppid`, with a new `resolved_by` response field identifying the hit path (`pid` / `cgroup` / `ppid`). cgroup takes precedence over ppid: cgroup is a container-level identity (stable across fork layers), while ppid is a process-level identity (breaks at depth > 1 or after setsid).
- **`virbius-kernel/src/pidmap.rs`** (P1): `redis_backup_async()` now writes a `cgroup_trace:{cgroup_id}` Redis reverse index. Agent registration writes both `pid_trace:{host_pid}` (primary index) and `cgroup_trace:{cgroup_id}` (reverse index); both keys point to the same JSON value and share a 3600s TTL. Skipped when cgroup_id = 0 (graceful degradation on macOS / cgroup v1).
- **`virbius-kernel/deploy/engine-service.yaml`**: new Engine K8s Service definition.
- **`virbius-kernel/deploy/falco-daemonset.yaml`**: new `config-subscriber` sidecar container that consumes Redis Stream to hot-reload Falco rule files.
- **`scripts/test-falco-cross-layer.sh`**: new macOS simulation test script covering 5 scenarios — pid direct hit, ppid fallback, cgroup grandchild process (ppid chain broken, cgroup hit), cgroup setsid detach (ppid=1, cgroup hit), and non-Agent filtering.

  - `falco_plugin` module declaration and exports in `lib.rs`
