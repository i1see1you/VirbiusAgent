🛡 接入 VirbiusAgent 防护说明 漏洞 → 能力 → 配置 → 生效（LLM01 · 提示注入 Prompt Injection）

1. 漏洞与本靶场

本关对应 OWASP LLM01 · 提示注入（Prompt Injection）。攻击者通过精心构造的输入，让模型忽略系统提示词、套取或泄露本不该说出的密码。

核心认知：模型输出是不可信的——它可能被输入诱导。因此对用户输入的审查必须独立于目标模型，由专门的防护引擎完成，而不是依赖模型自觉。

2. 用到的 VirbiusAgent 能力（本靶场：云层 LLM 语义检测 + 运营台 prompt 规则）

本关启用的是 virbius-engine 的云层提示词防护：用户输入先发到引擎 /v1/evaluate，由 LLM（VirbiusGuard）做语义注入检测，并叠加运营台 prompt 规则与 category-rule-mapping。

命中后按规则的动作与风险分处置（如 prompt-jailbreak → block），请求不会送达目标模型。这是独立于模型的第二道防线。

3. 在 virbius-control 上如何配置

· runtime = prompt（RuleRuntime.PROMPT，走运营台规则链）

· 通过 bind_scope 决定触发范围，经 categoryRuleMapping 映射到具体 prompt 规则

· risk_score / intent_action（block、deny 等）/ enforce_mode（full 才真正拦截，dry_run 仅计分）

· 规则本体在 control 运营台发布后经 RuleCache 加载，无需改 engine 配置文件

4. 如何生效

Control 发布规则 → engine 缓存加载 → 每次请求经 /v1/evaluate 评估 → 命中则 block/deny，否则放行。

页面右上角导航栏的「🛡 VirbiusAgent 防护」开关控制本关请求是否进入这条评估链：开启后注入请求会被拦截，关闭则直通目标模型。
