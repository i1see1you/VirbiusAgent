Before production use:

  - Set secrets.licenseMasterKey (>= 32 chars; do not leave the chart default)
  - Set secrets.apiKeyPepper (>= 32 chars; required because control.apiKeyEnabled=true)
  - Set secrets.redisPassword (Redis requires auth by default, redis.authEnabled=true)
  - Set secrets.kafkaSaslUsername / kafkaSaslPassword (Kafka SASL/SCRAM is on by default)
  - Set secrets.authBootstrapPassword (ops console login; default username {{ .Values.auth.bootstrapUsername }})
  - Set global.imageRegistry and docker login / imagePullSecrets
  - Cluster must already have an Ingress Controller (class {{ .Values.ingress.className }})

P0 security notes:

{{- if .Values.mysql.tls.enabled }}
  - MySQL TLS is ENABLED: control verifies the server certificate
    (sslMode=VERIFY_IDENTITY, CA at /certs/mysql-ca.pem). Track certificate
    expiry and rotate via mysql.tls.existingSecret before it lapses.
{{- else }}
  - MySQL TLS is DISABLED (mysql.tls.enabled=false). For production set it to
    true and provide server cert/key + CA (see values.example.yaml).
{{- end }}
{{- if .Values.kafka.saslEnabled }}
  - Kafka uses SASL/SCRAM-SHA-256 over PLAINTEXT. Accepted risk (P0): audit
    payloads traverse the cluster network unencrypted. Upgrade to SASL_SSL
    (P1) when Kafka spans hosts/networks or compliance requires it.
{{- end }}
  - Control starts with strict secret policy in the prod profile: missing or
    weak secrets / open datastore transports fail startup with an explicit
    violation list.
